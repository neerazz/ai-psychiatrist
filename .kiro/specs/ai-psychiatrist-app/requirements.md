# Requirements Document

## Introduction

This document specifies the requirements for an AI Psychiatrist Web Application that provides realistic, professional therapy sessions through an interactive web interface. The system features a single AI-powered psychiatrist agent with realistic facial animation, real-time audio/video processing, and comprehensive session management to deliver a therapeutic experience that mimics in-person psychiatrist consultations.

## Glossary

- **AI_Psychiatrist**: The artificial intelligence system that conducts therapy sessions
- **Patient**: The user receiving psychiatric care through the application
- **System**: The complete AI psychiatrist web application including all components and interfaces
- **Session**: A structured therapy interaction between the Patient and AI_Psychiatrist
- **Patient_Overview**: A document containing patient history and background information
- **Session_Summary**: A generated report documenting session insights and analysis
- **Avatar**: The visual representation of the AI_Psychiatrist with lip-sync capabilities
- **Transcript**: Real-time text display of the conversation between Patient and AI_Psychiatrist
- **Deep_Analysis**: Background AI processing for psychological insights and behavior detection
- **Connection_Status**: System indicator showing online/offline network connectivity
- **Local_Models**: On-device AI models for speech processing, text generation, and analysis
- **Memory_Directory**: Local storage system for patient data, sessions, and system state
- **Overview_Document**: Comprehensive snapshot document containing complete patient information
- **Session_Report**: Individual session-specific analysis and summary document
- **AI_Backend**: Configurable AI service provider (Claude, Gemini, etc.) for conversation processing
- **Config_File**: Configuration file that defines which AI_Backend and models to use
- **Infrastructure_Setup**: Automated system for installing and configuring required components (Ollama, models, etc.)
- **Self_Healing_System**: Automated error detection and correction system with code fixing capabilities
- **Vector_Database**: Database system for storing session embeddings and semantic search capabilities
- **Session_Database**: Relational database for storing session metadata and patient overview information
- **Vector_Embeddings**: Numerical representations of conversation content for semantic analysis
- **Embedding_Status**: Real-time indicator showing the status of vector embedding processes
- **Research_Thread**: Background processing thread for conducting detailed topic research
- **Clinical_Insights**: Advanced psychological analysis generated by Pro AI models
- **Sentiment_Analysis**: Real-time detection and analysis of patient emotional states and concerning patterns
- **Network_Status**: Visual indicators showing online/offline connectivity state
- **Dr_Sterling**: The AI psychiatrist persona with clinical expertise and therapeutic capabilities
- **Temperature_Settings**: AI model parameters controlling response randomness and clinical accuracy
- **Clinical_Directives**: Specific instructions for maintaining medical neutrality and therapeutic standards
- **Thinking_Budget**: Maximum token allocation for deep reasoning and analysis processes
- **Conversation_Highlight**: Real-time emotional or psychological state indicators displayed during Sessions
- **Speech_Engine**: The system component responsible for speech-to-text conversion
- **Video_Interface**: The dual-box display showing AI_Psychiatrist's animated face and Patient's camera feed (if enabled)
- **Context_Fetcher**: Support AI agent responsible for retrieving relevant patient context from Vector_Database
- **Deep_Researcher**: Support AI agent responsible for background research on topics and conditions
- **Analyst_AI**: Support AI agent responsible for needs assessment and session planning
- **Crisis_Agent**: Safety-focused AI component for detecting and handling crisis situations

## Section 1: Core Session Management

### Requirement 1: Session Lifecycle Management

**User Story:** As a patient, I want to participate in timed therapy sessions, so that I can receive structured psychological support within defined timeframes.

#### Acceptance Criteria

1. WHEN a Session starts, THE System SHALL display a timer showing remaining session time at the top of the interface
2. WHEN the Session timer reaches 20 minutes, THE System SHALL provide a 5-minute warning notification
3. WHEN the Session timer reaches 25 minutes, THE System SHALL automatically end the Session and generate a Session_Summary
4. WHEN a Session is in progress, THE System SHALL persist session state every 30 seconds to Memory_Directory
5. WHEN a Session ends, THE System SHALL prevent new conversation input and display session completion status
6. WHEN the Session timer is active, THE System SHALL show both elapsed time and remaining session time
7. WHEN the session approaches the minimum duration (5 minutes), THE System SHALL provide visual indicators

### Requirement 2: AI Psychiatrist Behavior

**User Story:** As a patient, I want to interact with an AI that behaves like a professional psychiatrist, so that I receive meaningful therapeutic guidance and analysis.

#### Acceptance Criteria

1. WHEN the Patient speaks, THE AI_Psychiatrist SHALL respond with professional therapeutic language and techniques
2. WHEN the AI_Psychiatrist detects emotional cues in Patient responses, THE AI_Psychiatrist SHALL ask relevant follow-up questions
3. WHEN the Patient mentions problems or concerns, THE AI_Psychiatrist SHALL probe deeper to uncover underlying issues
4. WHEN the AI_Psychiatrist identifies patterns in Patient behavior, THE AI_Psychiatrist SHALL connect related topics from the conversation
5. WHEN generating responses, THE AI_Psychiatrist SHALL maintain a collaborative and professional tone throughout the Session
6. THE AI_Psychiatrist SHALL use evidence-based therapeutic techniques (CBT, DBT, MI, etc.)
7. THE AI_Psychiatrist SHALL maintain context awareness across the entire session

### Requirement 3: Proactive Session Initiation

**User Story:** As a patient, I want Dr. Sterling to initiate our sessions naturally based on my history and current context, so that the therapy feels authentic and professionally guided from the start.

#### Acceptance Criteria

1. WHEN a session begins, THE Dr_Sterling SHALL proactively start the conversation based on patient history and context
2. THE Dr_Sterling SHALL reference previous sessions and current patient status in the opening remarks
3. THE Dr_Sterling SHALL set the therapeutic tone and agenda based on Overview_Document insights
4. WHEN greeting patients, THE Dr_Sterling SHALL demonstrate awareness of patient's current situation and recent developments
5. THE Dr_Sterling SHALL never wait passively for patient initiation but actively guide session opening
6. THE System SHALL ensure Dr_Sterling's opening reflects realistic therapeutic practice and professional engagement

## Section 2: Real-Time Communication

### Requirement 4: Speech-to-Text Processing

**User Story:** As a patient, I want to have natural voice conversations with visual feedback, so that the therapy session feels authentic and engaging.

#### Acceptance Criteria

1. WHEN the Patient speaks, THE Speech_Engine SHALL convert speech to text within 500ms (target: 200ms)
2. WHEN audio input is detected, THE System SHALL display a "listening" indicator
3. THE Speech_Engine SHALL handle pauses, sighs, and crying gracefully without timeout
4. THE Speech_Engine SHALL support continuous streaming transcription
5. WHEN silence exceeds 10 seconds, THE System SHALL prompt the patient gently

#### Technical Specifications

| Mode | Engine | Model | Latency Target | Latency Max |
|------|--------|-------|----------------|-------------|
| Online Primary | Deepgram | Nova-2 | 80ms | 200ms |
| Online Fallback | Google Speech-to-Text | v2 | 100ms | 300ms |
| Offline | Whisper.cpp | medium.en | 200ms | 500ms |

**Audio Parameters:**
- Sample Rate: 16000 Hz
- Bit Depth: 16-bit PCM
- Channels: Mono
- Silence Detection: VAD-based, 500ms threshold
- Profanity Filter: Disabled (clinical context)

### Requirement 5: Text-to-Speech Synthesis

**User Story:** As a patient, I want Dr. Sterling to have a professional, calming voice that enhances the therapeutic experience.

#### Acceptance Criteria

1. WHEN the AI_Psychiatrist responds, THE System SHALL synthesize speech within 400ms (target: 200ms)
2. THE voice SHALL maintain consistent quality and therapeutic appropriateness across all sessions
3. THE System SHALL support SSML for emotional modulation in responses
4. THE System SHALL provide fallback voice options if primary voice model is unavailable
5. THE voice SHALL use calming parameters: pitch 120-180Hz, rate 0.85-0.95x normal

#### Technical Specifications

## Section 8: Model Orchestration

### Requirement 20: Smart Model Orchestration Strategy

**User Story:** As a user, I want the system to intelligently select the best available AI models based on my API keys, prioritizing Claude Sonnet 4.5 for reasoning.

#### Acceptance Criteria

1. THE System SHALL check for API keys on startup in order: `ANTHROPIC_API_KEY` then `GEMINI_API_KEY`

2. IF ONLY `ANTHROPIC_API_KEY` is present:
   - THE System SHALL use **Claude Sonnet 4.5** (with extended thinking) for Dr_Sterling
   - THE System SHALL use **Claude Sonnet 4.5** for all support agents

3. IF ONLY `GEMINI_API_KEY` is present:
   - THE System SHALL use **Gemini 1.5 Pro** for Dr_Sterling (best available reasoning)
   - THE System SHALL use **Gemini 1.5 Flash** for support agents (speed-optimized)

4. IF BOTH `ANTHROPIC_API_KEY` AND `GEMINI_API_KEY` are present:
   - THE System SHALL use **Claude Sonnet 4.5** (with extended thinking) for Dr_Sterling (reasoning, theory of mind, therapeutic dialogue)
   - THE System SHALL use **Gemini 1.5 Flash** for Context_Fetcher (speed-optimized retrieval)
   - THE System SHALL use **Gemini 1.5 Pro** for Deep_Researcher (long context research)
   - THE System SHALL use **Gemini 1.5 Pro** for Analyst_AI (analytical tasks)

5. IF NO API keys are present:
   - THE System SHALL use Local Models (Ollama) for ALL agents
   - THE System SHALL display "Offline Mode - Limited Capabilities" warning

6. THE System SHALL display current model configuration in Settings/Status panel

#### Model Configuration Table

## Section 9: Connection Resilience

### Requirement 22: Hybrid Cloud/Local Architecture

**User Story:** As a patient, I want the application to use the best available AI models but seamlessly switch to local processing if internet fails.

#### Acceptance Criteria

1. THE System SHALL implement a Hybrid Architecture prioritizing Cloud Models when available
2. WHEN internet connectivity is active, THE System SHALL use configured Cloud Models for primary generation
3. WHEN internet connectivity fails, THE System SHALL seamlessly switch to Local_Models within 3 seconds
4. WHEN operating in Offline Mode, THE System SHALL notify the user but continue all core therapeutic functions
5. THE System SHALL synchronize locally generated session data with Cloud system once connectivity is restored
6. THE System SHALL maintain session continuity during network transitions with zero data loss

### Requirement 23: Network Status and Recovery

**User Story:** As a patient, I want the application to handle connection issues gracefully.

#### Acceptance Criteria

1. THE System SHALL display clear Connection_Status indicators (Online/Offline/Reconnecting)
2. WHEN network connectivity is lost, THE System SHALL switch to offline Speech_Engine within 1 second
3. WHEN connection is restored, THE System SHALL automatically reconnect and synchronize session data
4. WHEN connection failures occur during a Session, THE System SHALL preserve all conversation data locally
5. THE System SHALL implement automatic reconnection with exponential backoff (1s, 2s, 4s, 8s, max 30s)
6. THE System SHALL provide user feedback about connection status and recovery progress

### Requirement 24: Session State Persistence

**User Story:** As a patient, I want my session to be preserved even if something goes wrong.

#### Acceptance Criteria

1. THE System SHALL persist session state to Memory_Directory every 30 seconds during active sessions
2. THE System SHALL use CRDT (Conflict-free Replicated Data Types) for transcript merging
3. WHEN a session crashes, THE System SHALL offer "Resume Previous Session" on next load
4. THE System SHALL preserve minimum 95% of conversation data in crash scenarios
5. WHEN reconnection happens, THE System SHALL upload locally stored session data
6. THE System SHALL maintain audit trail of all state persistence events

## Section 12: Crisis Intervention

### Requirement 31: Crisis Detection

**User Story:** As a patient, I need the system to detect if I am in immediate danger and provide emergency resources.

#### Acceptance Criteria

1. THE System SHALL monitor all input for Crisis Keywords using tiered detection
2. WHEN a Tier-1 (immediate) crisis is detected, THE System SHALL trigger Safety Interruption Protocol
3. THE System SHALL display a prominent "Get Help Now" overlay with clickable emergency contacts
4. THE System SHALL NOT attempt to treat acute suicidality but strictly bridge to human emergency services
5. THE System SHALL log crisis events locally for patient review (privacy preserved)
6. THE crisis detection SHALL achieve >99% recall on Tier-1 indicators

#### Crisis Tier Definitions

**Tier 1 - Immediate Crisis (Highest Priority):**
- Active suicidal ideation with plan/intent
- Active homicidal ideation
- Current self-harm
- Immediate danger indicators
- **Response:** Immediate safety protocol, display crisis resources, pause therapeutic dialogue

**Tier 2 - High Risk (Elevated Monitoring):**
- Passive suicidal ideation
- Hopelessness expressions
- Self-harm history discussion
- Substance crisis indicators
- **Response:** Continue with safety assessment, increased monitoring, provide resources at session end

**Tier 3 - Moderate Concern (Increased Attention):**
- Severe depression symptoms
- Isolation statements
- Trauma disclosure
- **Response:** Continue conversation with heightened awareness, gentle check-ins
